# ADR-0018 — 核心定位 (客户管理为核心)

> **状态**: ✅ Accepted
> **拍板日期**: 2026-09-23
> **拍板人**: mm7 主人 (飞书 ou_b7dc078b75aa76960a16252688dbe6f9)

## 1. 上下文

项目治理层 §1 项目宗旨之前的描述为:

> "暖客宝 —— 大健康行业销售员的 CRM + AI 客户维护 + 养生记录,让养生销售有尊严地工作"

`README.md` 顶部 + AGENTS §1 也把"CRM + AI 客户维护 + 养生记录"作**并列三件套**陈列。但实际项目演进后,治理层描述与代码现状之间产生 drift:

| 缺口 | 现象 |
|---|---|
| **核心 / 手段未分层** | 三件套并列陈列, 没指出哪一个是**核心**, 哪一个是**手段** |
| **"分析"缺位** | 客户管理的关键动作之一 (record → manage → analyze) 完全没出现 |
| **"跟进指引"模糊** | "AI 客户维护"含糊, 没点出 AI 助手的产出形态 = **可执行的跟进指引** |
| **"付费率 + 加盟率"缺位** | 治理层完全没提商业目的; "加盟"只作为业务结构 (ADR-0006) 出现, 没作为业务目的 |

随着 Flutter 模块 (`modules/customer` / `modules/follow_up` / `modules/wellness`) 和 web admin (ADR-0017 解冻) 逐步清晰, 这种 drift 会让后续功能提案没有统一判据, 出现"做出来不算错但跟核心定位没关系"的功能。

## 2. 决策

**主人 2026-09-23 核实定位原话**:

> 「本应用的核心功能是客户管理。协助用户记录、管理、分析客户信息,给用户明确的行动(跟进)指引,进而提高用户付费率、加盟率。」

提炼为**四要素**:

| 维度 | 口径 |
|---|---|
| **核心功能** | **客户管理** |
| **三大动作** | **记录** + **管理** + **分析** |
| **行动输出** | **明确的跟进指引** (由 AI 助手承载) |
| **终极目的** | 提高**付费率** + **加盟率** |

**落地动作**:

- `docs/CHARTER.md §1.1` 一句话定义改写 — 由"CRM + AI 客户维护 + 养生记录" 改为 "核心 = 客户管理 (记录 / 管理 / 分析) + AI 助手跟进指引 → 付费+加盟转化"
- `docs/CHARTER.md §1.4` **新增** — 核心定位四要素 (含"对开发的影响"四问 + "角色重定义"子段)
- `AGENTS.md §1` 项目 vibe 同步 — 首行 + "核心交互"三件套对齐 §1.4
- `README.md` 顶部 + "这个项目是干嘛的" 改写 — 标题 / 四要素表 / 三件套 = 实现手段
- `CHANGELOG.md [Unreleased]` 加 `### Changed` 段

**CHARTER 版本号**: v0.1.5 → **v0.1.6**。

| 候选 | 评估 | 结果 |

## 4. 影响

### 4.1 对 Flutter / web admin 模块

- 任何新功能提案必答 **CHARTER §1.4 末段"四问"**:
  1. 服务于 **记录 / 管理 / 分析** 哪一个动作?
  2. 产出**跟进指引**吗? 可执行吗? (AI 能力不为炫技, 为可执行)
  3. 最终能 **提高付费率 / 加盟率** 吗? 不能 → 重做或砍掉
  4. 是否引入**金额 / 计酬**机制? (CHARTER §3.6 红线 = 否)

### 4.2 对 AI 域 (Phase 2 Copilot)

- **优先级重排**: **跟进指引的可执行性** > AI 能力本身
- 不为炫技 (例如"AI 随便聊聊养生"被砍, 不属于产出跟进指引)
- LLM prompt template 必含 "可执行下一步" 字段 (而不是开放式建议)

### 4.3 对加盟体系

- 加盟率 = "为加盟商带来可衡量的商业转化" (邀请转化只是手段)
- 不引入金额 / 计酬追踪 (CHARTER §3.6 红线保留)
- 通过**复购 / 转化代理指标**间接观测加盟率

### 4.4 对副标题 / 表现层

**副标题 (登录页 / PWA / metadata)** — 2026-09-23 落定, **2026-09-23 复核后维持不变**:

- 口径 = **`大健康客户管理・AI助手`** (13 字)
- 覆盖 4 处, 字符一致:
  - `flutter_app/lib/modules/auth/screens/login_screen.dart` (登录页大标题下)
  - `flutter_app/web/manifest.json` (PWA description)
  - `src/app/layout.tsx` (`<meta name="description">`)
  - `src/app/login/page.tsx` (web 登录页 title, 带 `· 登录` 后缀)
- 另修: `flutter_app/web/index.html` 的 `<meta name="description">` 原为**旧 tagline**
  (`养生行业销售人员的 CRM + AI 客户维护 + 养生记录系统`), 已同步 (commit `60f8b3b`, 2026-09-23)

**复核结论: 维持 A 案 (不改)** —— 主人 2026-09-23 拍板。

复核时评估过三个候选 (A 现状 / B `…・AI跟进指引` / C `客户管理・AI 跟进指引`):

| | 评估 |
|---|---|
| **A (采纳)** | 「大健康客户管理」覆盖 **核心功能**;「AI助手」是**载体**而非**产出**(丢「跟进指引」), 但**短、易记、无歧义**。长文场景 (README / CHARTER §1.4) 已把「跟进指引」讲清 —— **tagline 承载识别, 不承载完整定位**。 |
| B | 补齐「跟进指引」, 与 README 长文措辞一致; 但 16 字, 且「AI跟进指引」作产品副标略拗口 |
| C | 最短, 但丢「大健康」行业限定 (与 §1.2 覆盖细分行业冲突) |

**已知取舍 (主人知情并接受)**:

- 副标题**不含**「跟进指引」—— 即与 README §「核心差异」的措辞「客户管理 + **AI 跟进指引**」
  存在**详略差异** (README 是长文描述, 副标题是短标签)
- 2026-09-23 复核时此差异被提出 (判定「副标题落在 *AI 能力本身* 一侧, 与本 ADR §4.2 的
  『可执行性 > AI 能力』优先级有张力」), 主人**选择维持 A 案**:
  **短、易记、无歧义的识别性 > 副标题承载完整定位**
- 即: **不是"没发现", 是"发现了并主动接受"**。后续若有人认为该差异需修正,
  属**新决策**, 需重新拍板

**admin 概览页** —— 无产品副标题 (只有动态状态行 `暖客宝 v0.1 · 今天有 N 位客户待跟进`),
**不在定位对齐范围** (状态行动态生成, 不承载品牌定位)。

> **本条已闭环** —— ADR-0018 原文的「后续 UI tagline … 待下一轮 (本次未做)」**已做**, 见上。
> 后续若有人想改副标题, 属**新决策**, 需重新拍板 (不得以"ADR 说待办"为由自动推进)。

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 治理层改了, 实际功能没跟上 (e.g. "分析"还没真正落地) | §1.4 表格"当前落地"列明当前状态 ("现状弱, 后期 AI 域补强"); 不假装"分析"已经做好了 |
| "加盟率"被误解为"邀请人进 app 的转化率" | §1.4 + 本 ADR §4.3 明确 = "为加盟商带来可衡量的商业转化", 不是邀请转化率 |
| 旧描述残留在多处 (AGENTS / README / 副标题前代) | 本次一次性同步 4 个文件; 后续 PR 必引 CHARTER §1.4 |
| 新定位下"养生记录"角色降级引发反弹 | §1.4 "角色重定义" 段明确 = "养生记录" 仍是**复购 / 转化的核心数据源**, 投资不降; 角色降级 = **叙事优先级**, 不等于投资降级 |
| 加盟率追踪需要新指标 → 引诱引入金额字段 | §1.4 + 本 ADR §4.3 + CHARTER §3.6 三重防线; 复购 / 转化代理指标必须足够, 否则是定位错了不是 KPI 错了 |
