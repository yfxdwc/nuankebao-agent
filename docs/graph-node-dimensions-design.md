## 0. 需求 (主人 2026-09-17)

1. 节点要按**两个维度**区分:
   - **直推 / 非直推**: 直推 = 当前用户「我」直接引荐加盟的; 非直推 = 不是「我」直接引荐的 (我的上级或下级引荐而加盟)
   - **A线 / B线**: 原「左线/右线」改名为 **A线/B线**
2. 两个维度交叉 → 节点共 4 类: A线直推 / A线非直推 / B线直推 / B线非直推

## 1. 数据基础 (不改后端就能区分)

### 1.1 直推怎么判定

- 数据源: `franchisee.referrer_id` (推荐人, 见 `src/lib/db/schema.ts:81`)
- 图谱树 `/api/franchisees/me/tree` 是**按 referrer_id 连的推荐树** (`src/lib/db/queries/franchisee.ts:375` `buildTree` 用 `n.referrerId === root.id` 判父子)
- 所以: **树的第 1 层 (root 的直接子节点) = 我直推**; 第 2 层及以下 = 非直推 ✓
- 客户端判定: `depth == 1` → 直推; 不需要后端改动
  - 更稳的写法 (可选, 顺带做): 后端 `buildTree` 把 `referrerId` 也吐出来, 客户端判 `referrerId == 我.id` (为将来后端换成 placement 树留口)

### 1.2 A线 / B线 怎么判定

- DB 里字段值仍是 `left` / `right` (`placement_side`, schema 枚举不改)
- **A线 = 从「我」左边那一步下去的全部节点**; B线 = 右边那一步下去的全部节点
- 布局里已经在算: 每条腿 = 一列主线 + 外侧若干列 → 直接输出 `aLineIds` / `bLineIds` 两个集合给 painter

### 1.3 数据现状 (dev 测试树)

```
我(75) ── A线(左) 李建国(76) ── ... 共 15 层内节点 (depth 0-3 渲染, DB 里 31 节点)
        └─ B线(右) 王秀英(77) ── ...
我直推 = 2 个 (76/77); 其余 13 个 = 非直推
赞助关系: 15 个节点各带 ≤2 个直推 (referrer_id 分组无重复 side)
```

### 1.4 数据边界 (要在方案里说清楚)

| 情况 | 现状 | 本方案怎么处理 |
|---|---|---|
| **上级引荐的人** (我上级 referrer, 被放到我下线) | 树的父子是 referrer_id, 这个人 referrer_id ≠ 我 → **不会出现在我的图谱里** | 本页只能分「直推 / 非直推」两级; 要区分「上级引荐」需后端改成 placement 树 + 双维度 (建议先不做, 见 Q3) |
| **直推 > 2 人** (左右位满了, 算法 BFS 放到更深处, 但 referrer_id 仍是我 → 树里我有 3+ 个孩子) | 数据允许 (`franchisee-tree.ts` fallback 分支) | 现布局 `_childOn(left/right)` 只取每侧 1 个 → **会丢节点**; 本方案 P0.5 顺带修 (多余直推当外侧分支展开) |
| 同一个 placement_side 重复 (两侧都是 left) | 数据允许 | 同上, P0.5 按 children 顺序分配列 |

## 3. 视觉方案 (2 维 × 2 值)

### 3.1 编码原则

- 中老年为主 → 颜色 + 填充方式这两个**远看就能分辨**的通道优先; 文字角标只做辅助
- 保留现有语义: 绿 = 我, 橙 = 选中/高亮, 淡 = 被弱化
- 全景 (节点 ~19px) 时也要能分辨 → 不依赖小角标

### 3.2 色板候选 (A线/B线 用什么颜色)

| 方案 | A线 | B线 | 说明 |
|---|---|---|---|
| **① 蓝 + 紫 (推荐)** | 深蓝 `#2B6CB0` | 紫 `#8E5BA8` (沿用现有加盟紫) | 改动最小; 蓝/紫冷暖有别; 白字对比度都 ≥4.5:1 |
| ② 青 + 紫 | 深青 `#0F7B76` | 紫 `#8E5BA8` | 更"养生"气质, 但青跟根节点绿 `#4A7C59` 略近 |
| ③ 蓝 + 玫紫 | 深蓝 `#2B6CB0` | 玫紫 `#B0567E` | 色盲友好最强 (蓝 vs 玫红), 但品牌紫要换 |

### 3.3 直推 / 非直推 编码候选

| 方案 | 直推 | 非直推 | 说明 |
|---|---|---|---|
| **① 实心 vs 空心 (推荐)** | **实心**圆 (满色 + 白字) | **浅底 + 3px 同色描边** (底 18% 透明) | 全景/缩小都能分辨; 不增加视觉元素 |
| ② 只加角标 | 右上角小「直」圆标 (12pt 白字) | 无 | 全屏时清楚, 全景时角标融掉 → 不可靠 |
| ③ 描边粗细 | 白描边 4px (更"硬") | 白描边 1px | 老年人对小差异不敏感, 不推荐 |

> 推荐组合: **3.2 ① + 3.3 ①**, 再叠一个「直」角标 (放大 ≥0.6 时画, 缩小自动省掉), 即"远看色 + 近看标"。

### 3.4 推荐组合示意 (4 类节点)

```
        ● 我 (绿实心)                   ┌ 实心 = 直推
        │                               └ 空心 = 非直推
  ╭─────┴─────╮
  ● A直推    ● B直推          A线 = 蓝 #2B6CB0
  │            │               B线 = 紫 #8E5BA8
  ○ A非直推  ○ B非直推
  │            │
  ○ …          ○ …
```

### 3.5 各状态下的表现 (不能互相打架)

| 状态 | 表现 |
|---|---|
| 正常 | 按 3.2/3.3 画 |
| 选中/路径高亮 | 路径上的节点加橙环 + 连线橙色; 颜色仍保持 A/B 色 (不改成橙) |
| 搜索/未选中 | 未命中节点整体降透明度 (现有逻辑), 颜色/填充仍可辨 |
| 主线 | 主线连线加粗 (现有), 主线节点不额外改色 |
